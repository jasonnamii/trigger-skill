## §B. 정식명 31 verbatim 정의 (풀로드)

### 1. 홈즈
[전향] 세밀관찰 → 이상징후 탐지 → 복수가설 생성 → 증거대조 검증 → 결론도출 + 추론경로. [복기 모드] "끝났다·돌아본다" 명시 시 발동 — 결과에서 역추적 → 결정 분기점 식별 → 추론경로 재구성 → 다음 회차 적용 1~3개.

### 2. 오컴
경쟁가설 ≥3개 명시 강제 → 가설×설명력×기각사유 표 → 가정 최소 가설 1개 채택 + 나머지 기각 사유. 단일·이중 가설 = 미발동. 4개+ 허용.

### 3. 제1원리
유추·관행 차단 → 환원 불가한 자명 명제까지 분해 → 바닥부터 재조립.

### 4. 베이지안
사전확률 수치 가능 영역(의료·금융·R&D·예측) + 신규 증거 ≥1개 명시 시 발동. 사전확률 % → 신규 증거 → 사후확률 % 갱신표 강제. 수치 부재 영역(감성·정치·문화) = 미발동. 갱신 근거 명시.

### 5. 엄브렐러
주어진 요소 → 절대자 확장(동류 전수) → MECE 분류 → 상위 개념 명명 (우산도).

### 6. 아날로지
구조적 패턴 추출 → 타 도메인 사례 정확히 3개 매핑 → 적용 가능성 검증 (도메인×구조매핑×적용안 3행 표). 사례 3개 미만 = 미발동.

### 7. 연역수렴
L1 축별 독립 연역(원칙→적용→예외) → L2 축간 교차 연역(모순·강화·빈자리) → 통찰 + 추가 조사 영역.

### 8. 외과적
부분 수정 시 전체 MECE 구조 완전 유지 + 수정 범위 최소화 + 정합성 검증.

### 9. 백본
챕터 ≥5개 + 독자 스캔 의도 명시 시 발동. 챕터 단위 — 각 챕터 결론 먼저 → 역방향 추론 → 필수 논거만. 챕터 간 서사 흐름 유지로 백본만 읽어도 전체 서사가 잡히게. 단일 문서·단일 섹션 = paper-engine HERO가 처리, 백본 미발동. 스켈레톤=논리축과 분리: 백본=서사축.

### 10. 스켈레톤
군더더기 전부 제거 → 가장 심플한 논리 흐름만 (골격도).

### 11. SHE
Shrink(인지적 부담 축소, 기능 축소 ✗ '느낌'을 줄임) → Hide(복잡성 제거 ✗ 은닉, 유저는 결과만·시스템은 뒤로) → Embody(설명 ✗ 경험으로 전달, 몸으로 배우는 인터페이스). 본질 = "복잡한 시스템을 인간 직관으로 번역하는 기술". 함정: Shrink=기능줄이기 ✗ · Hide=UX단순화 ✗ · Embody=인터랙션추가 ✗ → 실체는 인지구조설계. 순서 S→H→E.

### 12. 엘베피치
청자 처음 듣는 사람 + 시간 ≤2분 명시 시 발동. 4문장 슬롯 고정: 후크 1줄 → 근거 2줄 → Ask 1줄. 슬롯 라벨 부착. VC·외부인·낯선 청자 한정. 슬롯 위반 = 발동 실패. 백본·스켈레톤과 차이: 엘베피치=구두 피치, 백본=서사축, 스켈레톤=논리골격.

### 13. 타임스톤
인과·선후관계 파악 → 시간축 정렬 → 순서 교정.

### 14. 맥가이버
제약조건 파악 → 가용자원 탐색·재해석 → 비표준 용도 발견 → 창의적 조합 → 즉시 실행.

### 15. 넛지
강제·금지 불가 상황 전제 → 디폴트값 / 프레이밍 / 이탈비용 3행 표 설계 → 선택 자유 보존 + 의도 방향 유도. "강제 못 쓰는데 행동 바꿔야 함" 명시 시 발동. 표 미산출 = 발동 실패.

### 16. 프리모르템
실패 확정 전제 → 역추적 → 치명 원인 Top 3 → 사전 차단책.

### 17. 트리아지
자원 제약 전제 → 긴급×중요 2축 → 즉시/예약/위임/제거 → 시퀀싱. 각 분기 항목 3개 권장(과부하 방지). 즉시 ≤30% 권장. 분배 비율 가이드: 즉시 ≤30% / 예약 30~50% / 위임 10~30% / 제거 ≥10%.

### 18. 줌
한 스케일에서 결론 굳어짐 감지 → 5스케일(개인·팀·조직·산업·사회) 중 ≥3개 대조표 강제 → 단일 시점 답변 차단. 단독 발동 시 대조표 미산출 = 발동 실패.

### 19. 절대자
①목표 선언 ②입력 팩터 수집 ③목표 기준 MECE 너비확장 ④수평적 복수 엄브렐러 청킹·명명 ⑤각 엄브렐러 하위 드릴다운 위임. 너비확장 ✓ 깊이확장 ✗.

### 20. 틀밖
①프레임 식별 ②프레임 고정 후 거부 ③3대 킬샷(이걸 안 하는 것 / 대상·구조·방식 자체 변경 / 아무도 안 묻는 질문) ④프레임 밖 답 없으면 종료문: "프레임 안 유효 — 현 프레임 내 최선책으로 회귀" 명시 후 종료.

### 21. 부작업
주작업 스냅샷 저장(목표·진행·다음) → TodoList 보존 → 부작업 진입.

### 22. 주작업
스냅샷 복원 → TodoList 로드 → 중단 지점 재개.

### 23. 수정4
파일 교체·삽입·삭제. L0~L4 영향범위 판정(L0 단일줄 / L1 단일파일 / L2 동일폴더 / L3 다른모듈 / L4 시스템전체) → 게이트 통과 → 외과적 3단계 실행. 풀버전 = `references/protocol-edit4.md`.

### 24. 복기
종료된 작업·캠페인·세션 명시 시 발동. 결정 / 실패 / 교훈 3섹션 → 다음 회차 적용 액션 ≤3개. "끝났다·돌아본다·복기" 키워드 hit. 홈즈 복기 모드와 차이: 복기=완결된 사건 회고, 홈즈복기=추론경로 역추적.

### 25. 이해당사자맵
이해 충돌·다자 의사결정 감지 시 발동. 당사자 N명 × 이익 × 반대 × 레버리지 4열 표 강제. 협상스킬·관리스킬 풀엔진과 차이: 이해당사자맵=경량 표 1장, 풀엔진=세션 단위. 당사자 ≥3명 권장.

### 26. 신뢰구간
예측·재무·전망 수치 출력 시 자동 발동. 단일 수치 보고 금지. low / base / high 3개 범위 + 핵심 가정 1줄 명시 강제. 수치 옆 [low–high] 범위 표기. 베이지안과 차이: 신뢰구간=표현 트리거(범위), 베이지안=갱신 트리거(확률).

### 27. 작업설계자
대화 맥락 기반 목표 재구성 + 실행 계획 설계. 7단계 출력 후 멈추고 승인 대기. 출력 끝에 "형이 결정해야 할 포인트 1~2개" highlight 강제. 풀버전 = `references/protocol-designer.md`.

### 28. 핑퐁
[컨펌게이트] ①대화 지속 의지 선언 ②질문·의견 대기 ③답변만, 실행 ✗ ④컨펌 시 다음 턴.

### 29. 리허설
[컨펌게이트] ①의견·컨설팅 수집 ②적용 결과 미리보기(dry-run) ③변경점 highlight ④컨펌 대기.

### 30. 작업계획
[컨펌게이트] ①Before/After 비교 ②갭 분석 ③타임라인 정렬 ④반영 계획 ⑤컨펌 대기.

### 31. 메타틀밖
Claude 자신이 시스템 개선·룰 신설·구조 설계 작업 진입 시 자가감지 강제. 4단계 동작:
①**자가감지** — 현재 답이 "기존 시스템 내부 정교화"인지 자문 (패턴 추가·룰 강화·정밀화·세분화 = YES)
②**자원 재해석** — YES면 시스템 자체를 자원으로 승격. 입력 형식·사용자 발화 프로토콜·Claude-사용자 인터페이스를 변경 가능 변수로 인정.
③**외부 처방 강제 생성** — 시스템 외부 처방 후보 ≥1개 강제 (1바이트 신호·입력 형식 신설·인터페이스 미세변경·발화 프로토콜 추가).
④**분리 출력** — 내부 처방 N개 + 외부 처방 ≥1개를 슬롯 라벨 부착해 분리 출력.

**출력 슬롯 고정:**
```
[내부 처방 — 시스템 안]
1. ...
2. ...
3. ...

[외부 처방 — 시스템 밖]
+1. ... (1바이트 신호·입력 형식 신설·인터페이스 변경)
```

**발동 실패 조건:** 외부 슬롯 공란 = 발동 실패·재생성. 슬롯 라벨 미부착 = 발동 실패.

**틀밖(§B 20)과 차이:** 틀밖 = 형 문제의 프레임 깨기(외부에서 본 형의 문제). 메타틀밖 = Claude 자신이 답 만들 때 자기 사고 프레임 깨기(내부 정교화 모드 차단). 영토 분리 — 둘 다 발동 가능하나 적용 대상 다름.

**자연발화 hit:** "강구해·더 잘·방법 없을까·어떻게 더·개선해줘·시스템 어떻게" 등 시스템 개선 요청 패턴. 점 트리거(`메타틀밖.`) = Rule 0 hard-fire.

## 32. 리팩토링팀 [팀 모드·자비스 디폴트]

작업자·연결자·감시자·검토자 4역할 N회 루프. 파괴적 변경(병합·삭제·구조 재편·DB 마이그레이션·코드 리팩토링) 전용.

- **작업자(Worker)** — 실제 변경 실행. 결정과 실행 분리.
- **연결자(Linker)** — 변경이 깨뜨릴 참조·의존성·호출관계 grep·매핑.
- **감시자(Watcher)** — 변경 직후 잔존·누락·깨진 링크·중복 grep. 작업자 시야 밖 패턴 검출.
- **검토자(Reviewer)** — 9룰·테스트·전체 정합성. 부분 OK ≠ 전체 OK.

**루프 종료:** 감시자 0건 + 검토자 PASS. FAIL 시 작업자 복귀.
**컨펌게이트:** ✗ (감시자·검토자가 게이트 역할). 자비스 모드면 종료조건까지 자동 반복.
**자연발화:** "리팩토링·통합·합쳐·정리해·깨끗하게·구조 재편·마이그레이션".
**점 트리거:** `리팩토링팀.` = Rule 0 hard-fire.

## 33. 기획팀 [팀 모드·≥2회 루프 강제]

기획자·작업자·비평가·수정자 4역할 ≥2회 루프. 창작·기획안·디자인·BP·제품 신규 산출 전용.

- **기획자(Architect)** — 골격·논리·구조·MECE 설계.
- **작업자(Worker)** — 실제 본문·시각·코드 작성.
- **비평가(Critic)** — 가차없이 지적. **다른 페르소나 강제** (VC 파트너·디자인 디렉터·고객·CEO 등 명시).
- **수정자(Polisher)** — 비평 반영해 다듬기. 비평가와 분리 필수(자기변호 차단).

**루프 종료:** 비평가 추가 지적 없음 + 형 컨펌. 최소 2회(1회는 자기변호 위험).
**컨펌게이트:** ✗ (비평·수정이 게이트). 페르소나는 형이 명시 안 하면 1줄 가정 후 진행.
**자연발화:** "기획·디자인·BP·만들어·창작·새로 짜·아이디어·제안서·기획안".
**점 트리거:** `기획팀.` = Rule 0.

## 34. 분석팀 [팀 모드·옹호/반대 분리 강제]

리서처·옹호자·반대자·판정자 4역할. 의사결정·전략 판단·투자·정책·중요 선택 전용.

- **리서처(Researcher)** — 사실·데이터·사례·증거 수집. 양면 자료 모두.
- **옹호자(Advocate)** — 안에 찬성하는 가장 강한 논리. *분리 호출 강제*.
- **반대자(Devil's Advocate)** — 안에 반대하는 가장 강한 논리. *분리 호출 강제*.
- **판정자(Judge)** — 양측 듣고 트리아지·결론·다음 액션.

**핵심:** 옹호·반대를 *한 에이전트가 다 하면 양다리* — 분리 호출 필수. 형이 "분석팀" 호출하면 4단계 순차 출력 강제.
**컨펌게이트:** ✗ (판정자 결론이 게이트). 형 컨펌 후 실행 분기.
**자연발화:** "분석·판단·결정해·해야 해 말아야 해·검토·찬반·전략 판단·투자해야 해".
**점 트리거:** `분석팀.` = Rule 0.

## 35. 탐정팀 [팀 모드·가설 ≥3 강제]

관찰자·가설러·검증자·결론자 4역할. 디버깅·원인분석·복기·실패 진단·사고 조사 전용.

- **관찰자(Observer)** — 증상·로그·증거·이상 징후 수집. 홈즈식 세밀관찰.
- **가설러(Hypothesizer)** — 경쟁 가설 **≥3개** 강제 도출 (오컴식).
- **검증자(Tester)** — 가설별 증거 대조·기각·채택.
- **결론자(Concluder)** — 채택 가설 + 추론 경로 + 다음 액션.

**기존 §B 1 홈즈와 차이:** 홈즈 = 1인 추론(단일 트리거). 탐정팀 = 4역할 분담(팀 모드·역할 출력 강제).
**루프 종료:** 가설 채택 + 검증 PASS. 가설 ≥3 미충족 = 가설러 복귀.
